# 社媒运营规范

## 一、先定三件事（动手前，在对话里写清楚）

1. **这条内容服务哪个平台、哪个市场、哪种人群**：小红书 = 中国家庭/实操信息；Instagram = 画面与氛围；Facebook = 国际客群与服务标准。三个平台不是同一篇的翻译。
2. **读什么当事实来源**：只能用站内已核实的内容（`src/content/{destinations,accommodations,experiences,journeys,journal,services}/` 与 `docs/image-asset-register.md`）。站内没有的事实（价格、房型、营业时间）先问用户，不凭空补。
3. **读者看完下一步做什么**：只用三类行动（完整行程规划 / 明确服务报价 / 联系顾问咨询），不发明新的行动号召。

业务优先级沿用站规：理解 > 信任 > 兴趣 > 行动 > 美感。

## 二、账号档案（缺了先建）

查 `docs/social-profile.md`。没有就用 3–5 个问题问用户，写进这个文件，之后所有内容以它为准：

- 各平台账号定位一句话；目标人群；
- 语气（亲切/克制/专业）、常用与禁用词；
- "不做"清单（红线）；
- 已验证有效的做法（复盘后回填）。

不要自己编账号定位。

## 三、选题矩阵（批量出选题）

**支柱**固定 3–5 个，取自站内真实板块，用用户语言，例如：完整旅行 / 酒店别墅 / 家庭与孩子 / 用车接送 / 滑雪 / 企业活动。向用户确认后再用。

**格式**用下表 6 种（改自 Easel 的 8 种，去掉"激励故事""现在 vs 未来预测"，它们容易逼人虚构案例和夸大趋势）：

| 格式     | 写法要求                                                                      |
| -------- | ----------------------------------------------------------------------------- |
| 实操教程 | 标题含一个可执行动作和明确结果。如"带两个孩子住巴黎，订房前先问酒店这 3 件事" |
| 深度解释 | 讲清"为什么这样安排"。如"为什么我们不建议第一天就进城"                        |
| 反常识   | 直接挑战一个常见做法，必须有站内事实支撑                                      |
| 现场观察 | 房间、餐桌、车门、雪山、私人空间这类"我正在经历它"的细节，少出现人            |
| X vs Y   | 两个具体对象对比，如"酒店 vs 私人别墅：带老人该选哪个"                        |
| 清单     | 含具体数字，数字必须是真实的                                                  |

输出：表格（支柱 × 格式，每格一个**具体可直接写的标题**），再挑 3–5 个最强选题并说明理由，保存到 `docs/social/选题矩阵-YYYY-MM-DD.md`。

规则：同一支柱下角度不重复；标题不泛泛（"关于酒店的内容"不合格）；不用破折号。

打分只看五项，各 1–5：**对人群有用 × 站内有真实素材 × 能引向咨询 × 画面可做 × 符合调性**，乘积排序。不做"稀缺性"这类对服务业不适用的维度。

## 四、写稿流程

### 小红书笔记（图文）

1. **素材清点**：先看有哪些真实图片（`docs/image-asset-register.md`、站内已有图）。真实图 > AI 生图。排除项永远有效：不用未授权第三方 logo，不暗示未确认的合作。
2. **选 1–2 个核心卖点**，不堆功能。判断：别家有吗（稀缺）× 解决什么具体麻烦（实用）× 读者一眼能看到吗（可感知）。
3. **图文结构**：封面 1 张 + 内容 3–7 张 + 结尾 1 张，3:4 竖版，每张 ≤80 字，一张只讲一个点。
4. **正文**：100–300 字，开头钩子 → 关键信息 → 一个行动。口语，像懂行的朋友，不像品牌腔。
5. **标题**：给 2–3 个备选。**话题标签** 5–8 个：核心词 + 场景 + 人群。
6. **去 AI 味**：删掉"首先/其次/综上所述""通过……来……""不仅……更……"；用短句、具体例子；不用"革命性/颠覆性/奢华体验"这类空话；不用破折号。
7. **中文版侧重**：微信沟通、中国家庭、儿童双床、司机、购物等实操信息。

### Instagram / Facebook

- 英文、法文各自写，不互译。法文侧重服务标准、当地专业度。
- **Instagram 细则（排名信号、10 种公式、轮播结构、标签、主页 9 项评分、周计划、发布前清单）见 [references/instagram.md](references/instagram.md)。**
- **Facebook 细则（排名信号、短帖、10 种公式、主页 9 项评分、评论回复模板、清单）见 [references/facebook.md](references/facebook.md)。**
- 两份细则里的"报告值"是社区实测，不是平台官方数据；发布时间窗口原版是美国时间，不适用，以账号自带洞察为准。
- 视觉：优先建筑细节、房间、餐桌、车门、雪山；避免埃菲尔铁塔仰拍这类游客照构图。
- **硬性规则：每一张图（轮播每一页）都必须有背景底图，不得做成纯色纯文字页；背景图不得与已发布帖子重复（对照 `docs/social/素材使用记录.md`，发布后登记）；每张图底部固定放 MYVIPSERVICE 和 myvipservice.com。**

### 价格

每条涉及服务的内容至少给一个起价量级（如"from €X"），数字必须来自站内或用户确认。

### 落盘

```
docs/social/YYYY-MM-DD-主题/
├── note.md        标题备选、正文、话题标签、每张卡的文字
├── images/        最终图片
└── check.md       发布前检查结果（见第六节）
```

## 五、开头钩子

每个主题出 6 条，每条 2 行：第 1 行开场（陈述句，不用问句），第 2 行反转。**每行 ≤40 字符，用代码数，不用肉眼**：

```bash
python3 -c "import sys;[print(len(l.strip()),l.strip()) for l in sys.stdin]" <<< "这里贴钩子"
```

6 种公式（改自 Easel，去掉了"涨粉月入"类个人蜕变和"借名人品牌"类权威借势，这两种会逼人编造数据或暗示未授权关系）：

| 公式     | 结构                             | 示例                                          |
| -------- | -------------------------------- | --------------------------------------------- |
| 具体数字 | 真实数字 + 现象 → 出人意料的做法 | 带两个孩子住 5 晚 / 我们只订了一间双床房      |
| 逆向认知 | 大家都说 X → 恰恰相反            | 人人都在订市中心酒店 / 带孩子其实该住郊外     |
| 场景切入 | 一个具体的瞬间 → 它说明的事      | 凌晨 6 点司机已在门口 / 因为航班延误了 2 小时 |
| 坦白取舍 | 我们不做 X → 因为 Y              | 我们不推荐一天赶三个城市 / 孩子撑不住         |
| 季节窗口 | 某个时间点 → 多数人没意识到      | 12 月的卢瓦河谷很安静 / 城堡几乎没有排队      |
| 人群共鸣 | 点名一类人 → 他们的具体麻烦      | 带老人去法国的家庭 / 最怕的是台阶和换乘       |

规则：开场不用问号；数字用阿拉伯数字；不含"可能/也许/大概"；不含填充词；示例中的数字和事实必须换成真实的。选一条后再扩写成完整帖子。

**平台专用公式**：Instagram 的 IG1–IG10（文案 / 轮播 / Reels 三个钩子位置）见 `references/instagram.md`，Facebook 的 FB1–FB10 见 `references/facebook.md`。

**拆解别人的爆款**：用户贴来一条帖子的文案（轮播要贴每张图上的字，Reels 要描述前 3 秒），输出：用了哪种公式（不确定就给前两名）→ 结构拆解（钩子、主体、收尾）→ 它追求的目标（收藏 / 发送 / 评论 / 关注）→ 为什么有效 → 一个带 `{空位}` 的空白模板 → 原帖里不该照抄的问题（互动诱导、乱用标签、夸大数字）。**只学结构，不抄原文**，涉嫌洗稿的用 Easel 式原创度自查：改写后与原文没有连续相同的句子。

## 六、发布前检查（逐项过，写进 check.md）

**合规（改自 Easel 的 quality-gate，已按本站去掉抖音/B站规则）**

- 绝对化用语：最、第一、唯一、100%、保证、独家。无数据支撑的一律改。
- 虚假宣传：不虚构客户数量、星级、奖项、合作关系、用户评价；不夸大效果。
- 版权：图片、音乐、第三方 logo 有授权吗？有疑问查 `docs/image-asset-register.md`。
- 小红书特有：①不在笔记和评论区留微信号、二维码、群号、外站链接（变体、谐音、emoji 暗示也算）；联系方式放主页简介或走私信，**以平台当前规则为准，发布前核对**。②有商业合作或利益关系要标注。③不用"闭眼入、冲"这类刷屏话术。

**调性（改自 Easel 的 persona-check）**

对照 `docs/social-profile.md` 看：定位是否对、人群是否对、语气是否对、有没有碰红线。调性只做**提醒**，不阻止发布；合规问题才是硬门禁。

**质量**

- 图片：尺寸对、与文字一致、无缺图、无占位文案。
- 无开发/占位文案，无"如上/如下"类指代错位。
- 行动只有三类之一。

**结论**：✅ 可发 / ⚠️ 改完再发 / ❌ 返工。合规高风险一律 ❌。最多返工一次，仍有问题就如实告诉用户，不反复改。

**发布动作**：发布、评论、回复都是对外动作，**逐条拿到用户明确同意后才执行**。小红书可用 `mcp__xiaohongshu-mcp__publish_content`；Instagram/Facebook 无接口，只给成品由用户发布。

## 七、复盘

数据来源：小红书用 `get_feed_detail`、`user_profile`、`list_notifications`；其他平台由用户提供截图或数字。没有数据就明说"无数据支撑，仅为结构性判断"。

**单条复盘**：判定（好/一般/差，写依据）→ 一句话核心成因 → 逐项看：开头钩子、结构、选题与人群匹配、平台适配、发布时间、封面视觉（各 1–10 分，附证据）→ 区分内容原因和运气因素 → 3 条按优先级排序的改进建议。

**规律提炼**：至少 5 条内容才做，样本少就提示结论不稳。对比好坏两组在钩子类型、选题、结构、长度、标签、封面上的差异，总结可复用做法。

**竞品与同类账号分析**（改自 sergebulaev 的 audience-insights，数据由用户贴数字或截图，暂不接 Apify 抓取）：

1. 读账号：粉丝数、发帖数、简介、分类、发帖频率；Facebook 另读评论。
2. 排序时**按粉丝数归一化**再判断赢家，否则学到的是"大账号效应"而不是"好内容"。
3. 找规律：钩子形状、文案长度、单图 / 轮播 / Reels、有没有具体数字。**规律必须在多条高表现内容里重复出现才算，一条不算。**
4. 评论归类：提问、认同、反对。反复出现的问题就是选题；有实质内容的评论是回复对象。
5. 输出行动清单：多做什么形式、关注哪些账号、哪些钩子交给第五节拆解。
6. 诚实边界：Instagram 看不到别人帖子的点赞者和评论者名单，Facebook 看不到点赞者名单；公开数据不是私有洞察（没有触达和人口统计）；数据不足就说"数据不足"，不编造任何帖子、数字或规律。
7. 只分析公开页面，不碰私人账号。

**本站最重要的指标不是点赞，而是咨询质量**：评论和私信里有没有人问行程、报价、日期。点赞多但没人问，说明吸引来的不是目标客户。把这个写进每次复盘。

复盘结论回填到 `docs/social-profile.md` 的"已验证有效的做法"。

## 八、不做的事

- 不虚构数据、案例、评价、奖项、合作方。
- 不把一篇稿子机械翻成另外几种语言。
- 不新增品牌色、按钮样式、行动号召类型。
- 不在没有用户同意的情况下发布、评论、回复。
- 不把核心入口绑定 Google 系或 YouTube；微信/WhatsApp 要有真实可用的入口说明。


## 发帖硬性规则补充（2026-10-07）
- 主帖（轮播/相册）**至少 6 张图**，每张真实底图、互不重复；轻帖单图不受限。
- 首图直接写主题；后面各页字少，首页可以多一些信息。
- 首页如有"现在有什么"这类信息，**分条写**（每项一行），字体不必加粗，让人看得清楚。
- 图上不画品牌/人物小标签，用真实标签。详见 `docs/social/SOP-每次发布流程.md` 第七、八、九节。
